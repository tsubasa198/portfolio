# タッチ端末の静的表示化と大画面レイアウト拡大 設計書

日付: 2026-07-26
状態: 承認済み(ユーザー確認済み)

## 背景

- タッチ端末ではスクラブ演出が操作感・発熱の面で合わず、静的表示のほうが良いという判断。
- Studio Display級の大画面(論理2000px超)では、コンテンツ上限幅1160px固定のため
  余白(暗闇)が過大になり、особにプロセス各シーンと制作実績で目立つ。

## A. タッチ端末の静的表示

### 判定

- `(hover: none) and (pointer: coarse)` … 主入力がタッチの端末(スマホ・タブレット)。
  タッチ対応ノートPC(hover可能)は対象外。
- 判定は読み込み時に1回。OSの `prefers-reduced-motion` と OR で合流させる。

### 挙動

既存の「モーション低減時の静的フォールバック」をそのまま使う:

- 動画(`preload="none"`化)・スクラブ・ピン留め・Canvas・Lenisを一切起動しない
- ヒーローはポスター+静止マスコット、各シーンは通常スクロールの縦積み
- CSSは既存の `body.reduced-motion` セレクタ群を流用(新レイアウトは作らない)

### 実装

- `src/core/staticMode.ts` に判定ヘルパーを新設(TDD)
  - `TOUCH_STATIC_MEDIA_QUERY` 定数
  - `shouldUseStaticPresentation(prefersReducedMotion, touchPrimary)`
- `main.ts` の `reducedMotion` 算出をヘルパー経由に変更

## B. 大画面(幅1600px超)のコンテンツ拡大

`@media (min-width: 1600px)` を新設し、1600px以下の表示には影響させない。

1. 実績カード: `.works-flight-cards` の上限幅 1160px → 約1600px
   (行シフト量 `finalCardRowShift` は実測式のため自動追従)
2. プロセスのデモ画面(`.macbook` 系): 上限を約1000px級へ拡大
3. 見出しタイポグラフィ: 大画面のみ1〜2割拡大
4. 録画で見えた「制作実績02タイトルとヘッダーの重なり」はセクション退場中の
   遷移状態であり静止時は発生しない(2048x1152で確認済み) → 対象外

## 検証

- vitest全件 + tsc + 本番ビルド
- Playwright: タッチエミュレーションで静的表示・通常スクロール動作
- 2048x1152 / 2560x1440 のスクリーンショットで余白改善を目視確認
- 1511x819(現行基準)が変化していないことを確認
