# ファーストビューのレイヤー分解による高画質化

**日付:** 2026-07-20
**対象:** ファーストビュー（スクロール前の静止状態）
**状態:** 実装済み

## 実装で当初設計から変わった点

当初は既存素材から背景を自動除去する前提だったが、素材に透過がなく市松模様が
焼き込まれていたため断念した。淡い発光は市松との輝度差が7しかなく、圧縮ノイズ
と同程度で分離できない。3手法を試して品質条件を満たせず、素材を純黒背景で
出し直す方針へ切り替えた。

これに伴い合成方式が変わった。

- 発光素材（ポータル・軌道・UIパネル・光球）は純黒背景のまま `mix-blend-mode: screen`
  で合成する。screenは `1-(1-a)(1-b)` なので黒が透明として振る舞う
- 台座は金属の非発光物でscreenだと暗部が浮くため、シルエットを外周からの
  flood fill で求めてアルファを生成する
- ポータルはリングと内部光が一体の素材として届いたため、レイヤーが1枚減った
- UIパネルが3種類とも別素材で届いたため、素材の使い回しが不要になった
- 光球が個別ファイルで届いたため、スプライトシートの切り出しが不要になった

またラッパー要素に `z-index` / `translate` / `opacity` のいずれかがあると
stacking context が生まれ、内側の screen が背景と混ざらず黒い矩形が出る。
このためラッパーは座標系の付与だけに徹し、重なり順は子要素の z-index、
フェードは子要素への直接指定で行っている。

## 背景と課題

ファーストビューの背景は `hero-idle-background.png`（1672×941）1枚に、ポータル・台座・UIパネル・球体・軌道がすべて焼き込まれている。Retinaディスプレイでは2倍の3344×1882相当が必要なため、全体が引き伸ばされてぼやける。特にポータルの光や台座のディテールなど、高周波成分を持つ要素の劣化が目立つ。

加えてUIパネルはCSSで描いた輪郭線であり、見本の立体的な発光ガラスパネルに対して質感が見劣りする。

## 解決方針

要素ごとに分解された素材（`画像/ファーストビューの画像/2-2〜2-9.png`）を個別レイヤーとして配置する。焼き込みをやめることで、目立つ要素は素材本来の解像度で描画され、Retinaでも鮮明になる。

### 解像度の妥当性

| 要素           | 素材                    | 画面表示 | Retina必要量 | 判定                                         |
| -------------- | ----------------------- | -------- | ------------ | -------------------------------------------- |
| ポータルリング | 2-2 (1254px)            | 約288px  | 576px        | 足りる                                       |
| ポータル内部光 | 2-3 (1254px)            | 約300px  | 600px        | 足りる                                       |
| 軌道線・粒子   | 2-4 (1672px)            | 全画面   | 2880px       | 不足だが線と粒子のみで劣化が目立たない       |
| 台座           | 2-5 (1448px)            | 約691px  | 1382px       | 足りる                                       |
| UIパネル       | 2-6 / 2-7 (1254px)      | 約120px  | 240px        | 余裕                                         |
| 球体           | 2-8切り出し (各約250px) | 約60px   | 120px        | 余裕                                         |
| 背景           | 2-9 (1672px)            | 1440px   | 2880px       | 不足だが暗いグラデーションのみで認識できない |

背景と軌道は必要量に届かないが、いずれも低周波成分が主体で劣化が視認されない。現状の問題は高周波成分を持つポータルと台座の劣化であり、そこは完全に解消される。

## アーキテクチャ

### 既存構造の再利用

`.hero-detail-layer`（z-index 6）を器として再利用する。この要素は既に以下を満たしている。

- `portalTransitionTimeline.ts` がタイムラインに接続済みで、`heroIdleHandoffEnd`(0.018) で `autoAlpha` によりフェードアウトする
- `transform-origin: 72% 52%` によりポータル中心のズームが効く

中身のCSS描画span 7個（orbit×2, panel×2, particle×3）を実素材の `<img>` に置き換える。**器を維持するため、スクロールで動画へ切り替わる仕組みには一切変更を加えない。**

### レイヤー順序

現行のz-index体系（背景3 / 装飾6 / マスコット7）を維持する。

| z-index   | 要素                         | 素材                           |
| --------- | ---------------------------- | ------------------------------ |
| 3         | 背景・床の反射               | 2-9                            |
| 6 (内部1) | ポータル内部の光             | 2-3                            |
| 6 (内部2) | ポータルリング               | 2-2                            |
| 6 (内部3) | 軌道線・粒子                 | 2-4                            |
| 6 (内部4) | 台座                         | 2-5                            |
| 6 (内部5) | UIパネル×3                   | 2-7 左上 / 2-6 右中 / 2-7 右下 |
| 7         | マスコット（**変更しない**） | 既存                           |
| 8         | 手前の球体×2                 | 2-8切り出し                    |

台座はマスコットの足元に位置するため装飾層に置く。手前の球体のみマスコットより上に新設する。

UIパネルは見本の配置に従い3枚とする。素材は2種類のため 2-7 を2枚、2-6 を1枚使う。

### 素材の前処理

Playwright付属のChromiumでWebP（品質92）へ変換する。追加の依存パッケージもネットワークアクセスも不要。

実測で 9.65MB → 0.71MB（93%削減）。現行の `hero-idle-background.png` が1.5MBのため、**全素材をレイヤー化しても初期読み込みは現状より軽くなる**。品質92は目視で劣化が確認できないことを検証済み。

2-8 は球体16個が並んだスプライトシートのため、変換時に個別へ切り出す。

変換スクリプトは `scripts/build-hero-assets.mjs` としてリポジトリに残し、素材差し替え時に再実行できるようにする。生成物は `public/assets/hero/` に配置しコミットする。

### アニメーション

レイヤーが独立するため視差表現が可能になる。すべてCSS `@keyframes` で完結させ、JSは変更しない。

| 要素           | 動き                                        |
| -------------- | ------------------------------------------- |
| ポータル内部光 | ゆっくりした明滅（呼吸）                    |
| ポータルリング | 微回転                                      |
| 軌道線         | リングと逆方向のドリフト                    |
| 台座           | 静止（マスコットの接地を保つ）              |
| UIパネル       | 上下浮遊（既存のfloatアニメーションを踏襲） |
| 球体           | 上下浮遊（パネルと位相をずらす）            |

`prefers-reduced-motion` 時は既存の仕組みどおり全アニメーションを停止する。

## テスト

### 既存テストの維持

- `pageContract.test.ts` が `hero-idle-background.png` のパスを検証しているため、WebP化に伴いテスト側も更新する
- `heroIdleAssets.test.ts` が実ファイルの解像度と透過を検証しているため、新素材に合わせて更新する

### 追加するテスト

**ハンドオフ健全性の検証**（最重要）
新レイヤーが全てハンドオフ対象（`.hero-detail-layer` の内側、または明示的にタイムライン接続済みの要素）に含まれることを検証する。将来レイヤーを追加した際に、動画への切り替えから取り残される事故を防ぐ。

**アセット存在の検証**
生成された全WebPが存在し、透過を持ち、期待する解像度以上であることを検証する。

**レイヤー順序の検証**
z-index が設計どおりの順序（背景 < 装飾 < マスコット < 手前球体）になっていることを検証する。マスコットが台座に埋まる、パネルがマスコットを覆うといった破綻を防ぐ。

## 制約

- **マスコット（`hero-mascot-idle-alpha.png`）には手を加えない** — 既に高画質で分解済み
- **スクロールで動画に切り替わる仕組みを壊さない** — `.hero-detail-layer` を器として維持することで担保する
- `index.html` の編集はフォーマッタが全体を再整形するため、行番号を限定した置換で行う（`pageContract.test.ts` が改行位置に依存しているため）

## 検証方法

1. テスト全件パス、`tsc --noEmit` クリーン、本番ビルド成功
2. ブラウザ実機で404ゼロ・コンソールエラーゼロ
3. スクロール0%（静止）→ 2%（ハンドオフ完了）→ 10% の各時点をスクリーンショットで確認し、動画への切り替えが従来どおり行われることを目視検証
4. devicePixelRatio 2 でスクリーンショットを撮り、ポータルと台座が鮮明であることを変更前と比較
